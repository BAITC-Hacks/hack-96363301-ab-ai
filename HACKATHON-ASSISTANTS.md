# Помощники Ab.Ai

Подготовлено 20.09.2026: инструкции помощников разработки, без реализации конкурсного кейса.

## Запуск

Открой PowerShell:

```powershell
codex -C D:\dev\hack-96363301-ab-ai
```

Или открой эту папку в приложении Codex и начни новую сессию.
Если клиент запрашивает доверие к проекту, проверь инструкции и подтверди доверие для загрузки настроек проекта.
Нужен действующий вход в Codex; при отсутствии входа используй `codex login`.
Роли лежат в `.codex/agents/`. Модель наследуется из текущей сессии.
Планировщик и проверяющий настроены на режим только чтения; ограничения текущей сессии также применяются.

Вставь в новую сессию:

> Ты координатор команды Ab.Ai. Отвечай по-русски. Кейс: [условия]. Осталось времени: [время]. Используй hack_planner для короткого плана MVP, hack_builder для ограниченных задач с явным списком файлов, hack_reviewer для проверки результата. Сам интегрируй изменения и запускай необходимые проверки. Параллельно выполняй только независимые задачи. Не позволяй двум исполнителям менять один файл. Не делегируй простые действия ради делегирования. Следуй HACKATHON-ASSISTANTS.md.

Проверка загрузки ролей без разработки:

> Запусти hack_planner: прочитать README.md и предложить три вопроса для уточнения будущего кейса. Ничего не изменять. Сообщи, удалось ли запустить именно эту роль.

Если роль не найдена, проверь папку сессии и доверие к проекту.
Запасной вариант: попросить обычного агента прочитать TOML нужной роли и выполнить задачу по его инструкциям. Это не проверяет механизм пользовательских ролей.

## Помощники Claude Code

Параллельный набор в `.claude/`: агенты `hack-planner`, `hack-builder`, `hack-scout`, `hack-reviewer`, `hack-pitch` и команды `/hack-start`, `/hack-tick`, `/hack-check`, `/hack-ship`. Контекст и правила координации — в `CLAUDE.md`.

Запуск:

```powershell
claude
```

Новые агенты подхватываются при старте сессии. Проверка загрузки без разработки:

> Запусти hack-planner: прочитать README.md и предложить три вопроса для уточнения будущего кейса. Ничего не изменять.

## Прогресс и материалы

Подтверждено официальными карточками правил (проверено 20.09.2026):

- Check-in 09:00–12:00 офлайн на локации, соревновательная часть 13:00–18:00, оставаться на территории до официального завершения.
- Каждый отчётный час — подтверждаемый прогресс. Категории: `CODE`, `FEATURE`, `MODEL`, `TEST`. Отсутствие почасового прогресса — дисквалификация.
- Вся работа после старта — только в `github.com/BAITC-Hacks/hack-96363301-ab-ai` (создан платформой edu.astanahub.com). Другой репозиторий как основной — дисквалификация.
- Любые AI-инструменты и AI-агенты разрешены прямым текстом (правило 03). Этот набор помощников регламенту не противоречит.
- Свои модели, библиотеки, шаблоны и датасеты раскрываются в README. Проект, преимущественно созданный третьими лицами без раскрытия этого факта, — дисквалификация. Раскрытие снимает вопрос.
- Выход с площадки более чем на 60 минут — дисквалификация.
- Запрета на подготовку до старта в правилах нет; чек-лист прямо требует заранее зайти в командный GitHub и настроить AI-инструменты.

Практика: каждые 45–50 минут проверять изменения, сохранять содержательный commit с категорией в префиксе и пушить.
Чат не является фоновым таймером: установи напоминания на телефоне.
Commit/push выполняет главный агент, когда это поручено пользователем; помощники возвращают результаты координатору.
Не создавай пустые коммиты ради отчётности и не меняй даты истории.
