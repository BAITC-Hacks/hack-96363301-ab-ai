# Проверка загрузки ролей после перезапуска

Подготовлено 22.09.2026. Файл локальный — лежит в `.claude/`, который исключён из индекса через `.git/info/exclude`.

Рядом: [`runbook.md`](runbook.md) — порядок действий 23 сентября · [`stack-notes.md`](stack-notes.md) — стек и грабли окружения.

Цель — убедиться, что агенты загрузились **из текущих файлов**, а не из устаревшего снимка реестра. Правки в определениях агентов внутри уже идущей сессии подхватываются ненадёжно, поэтому проверка имеет смысл только в свежей сессии.

Задавай каждому агенту его вопрос и сверяй с ожидаемым ответом. Агент, ответивший мимо, работает по старой инструкции — нужен ещё один перезапуск.

## 1. `hack-planner`

> Назови поимённо выданные команде ресурсы, которые обязан рассмотреть до предложения внешнего платного сервиса. На какие две вещи помимо кода всегда резервируешь время? По каким трём критериям выбираешь кейс, если их дали несколько?

**Ожидается:** OpenAI API (кредиты, провайдер по умолчанию), NVIDIA Build, NVIDIA Brev, офлайн-колёса `D:\dev\wheels`, npm-кеш, Docker-образы, PostgreSQL 17, ffmpeg · время на README по списку организаторов и на отдельный шаг «Сдать решение» · критерии выбора: **проверяемость «готово»**, количество обязательных требований (3–5 берём, десять размытых — мимо), совпадение с готовым окружением.

## 2. `hack-builder`

> Что обязан иметь любой вызов модели и почему? На каком SDK пишешь LLM-часть? Что делаешь при упоре в rate limit и что запрещено?

**Ожидается:** **демо-режим без API-ключа на фикстурах** — оценка заочная 24–28 сентября, у эксперта нашего ключа не будет, без фолбэка проект не оценят; демо-путь проходится целиком с пустым ключом · OpenAI SDK, ключи из переменных окружения · при лимите — к координатору, обход запрещён.

## 3. `hack-scout`

> Что проверяешь первым делом до предложения нового внешнего сервиса? Можно ли обойти rate limit вторым аккаунтом? Какая версия Python и на что это влияет?

**Ожидается:** сначала уже выданные ресурсы · обход запрещён, вместо него кеширование, батчинг, модель полегче · Python 3.14, нужны колёса `cp314`, иначе сборка из исходников.

## 4. `hack-reviewer`

> Назови первые два пункта своего списка приоритетов проверки — дословно.

**Ожидается:** (1) невыполненное обязательное требование кейса, (2) зависимость демо-пути от API-ключа. **Если первым назовёт баги демо-пути — реестр устарел**, это главный индикатор.

## 5. `hack-pitch`

> Сколько пунктов в обязательной структуре README организаторов? Какую таблицу обязан дать в разделе «как проверить решение»? Какой шаг напоминаешь координатору помимо README?

**Ожидается:** 11 пунктов · **таблицу трассировки требований**: требование кейса дословно → файл → команда проверки · напомнить про сдачу на платформе кнопкой «Сдать решение», push в GitHub сдачей не считается.
