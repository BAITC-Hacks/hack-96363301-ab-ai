## 13:00 — старт, задание опубликовано

### Шаг 1. Снять локальные исключения

До старта `.claude/`, `.codex/`, `CLAUDE.md` и `HACKATHON-ASSISTANTS.md` скрыты от git через `.git/info/exclude`. Скажи координатору:

> Старт объявлен. Сними заготовки из `.git/info/exclude`, закоммить `.gitignore` и подготовительные файлы.

### Шаг 2. Сохранить кейс в файл

**Не вставляй длинный текст кейса прямо в команду** — он обрежется и потеряется между сессиями. Скопируй условия и критерии оценивания в файл:

```

```

Если кейс на сайте и копировать неудобно — сделай скриншоты, сложи в `Downloads` и дай пути: координатор прочитает изображения.

Обязательно нужны **и текст кейса, и официальные критерии оценивания**. Планировщик откажется строить план без критериев — это сделано намеренно, жюри судит именно по ним.

### Шаг 3. Запустить работу

```

```

Дальше координатор сам:
- поднимет `hack-planner` — выбор кейса, демо-сценарий, критерии приёмки, вехи;
- при необходимости `hack-scout` — если нужен внешний API или датасет;
- запишет план в `CLAUDE.md`, раздел «Текущий кейс»;
- начнёт первую веху — сквозной скелет на заглушках.

Если кейсов в треке несколько — приложи все, планировщик выберет один и обоснует выбор.

## Если нужно запустить агента отдельно

Обычным языком, без синтаксиса:

> Запусти `hack-scout`: нужен рабочий способ распознавать текст с фото чека, верни минимальный пример под наш стек.

> Запусти `hack-builder` на парсер: файлы `src/parser/*.ts`, остальное не трогай.

> Запусти `hack-reviewer` по демо-пути.

Правила координации: один файл — один исполнитель; общие интерфейсы правит только координатор; мелочь быстрее сделать самому, чем делегировать.
