Реальный ответ сохранён без ручного редактирования в `server/fixtures/llm/verify-changes-v2.010d7421f7670f01.json`. Повтор анализа того же комплекта, с теми же именами файлов и моделью, при пустом `OPENAI_API_KEY` воспроизвёл ответ с `source: fixture`, 2 принятыми сопоставлениями и 0 отклонённых ссылок. Воспроизведение не называется живым вызовом.

Проверка подтверждает работающий доступ к API, прохождение схемы, допустимые ссылки и сохранение ответа. Она не доказывает качество смыслового сопоставления на произвольных документах. В сыром ответе модель категорично описала ненайденное соответствие как удаление функции; приложение не публикует свободный `rationale`, а формирует осторожное пояснение о необходимости проверки утраты или переформулировки. Это поведение проверяет `server/test/live-fixture.test.js`.

Для проверки без расходов: из каталога `server` выполнить `node --test test/live-fixture.test.js`. Тест отключает API. Для нового живого прогона: `npm run check:openai`, затем на запущенном сервере нажать «Проверить учебный пример». Каждый такой анализ с ключом выполняет новый API-запрос; существующая запись служит резервом, а не отменяет вызов.
