# Демонстрация OrgDiff — 90 секунд

## Основная мысль

«OrgDiff сравнивает подразделения и функции, находит возможные потери, пересечения и конфликты, показывает источник каждого вывода и готовит заключение. Дополнительная модельная проверка помогает заметить переформулировку даже без общих слов, а контрпроверка — изменение полномочий из-за одного слова».

## Подготовка

Открыть три вкладки: отчёт комплекта организатора, «Найти переформулировки», «Найти скрытые изменения». Последние два комплекта **синтетические**, их XLSX доступны для скачивания. Перед показом проверить состояние модельного шага: `api` означает живой ответ, `fixture` — воспроизведение сохранённого. В презентации назвать фактический источник; ожидание API не входит в 90 секунд рассказа.

## Маршрут

1. **0–12 секунд — подразделения.** Во вкладке организатора показать созданные и сохранённые подразделения. Назвать один результат и раскрыть его источник. Это первый обязательный результат задачи.
2. **12–25 секунд — функции и доказательства.** На карте выбрать передачу 5.4.4б → 5.3.3б и показать обе цитаты. Затем открыть одну возможную утрату: «Алгоритм не нашёл пару; потеря требует проверки». Закрыты сопоставление функций и прослеживаемость до исходного пункта.
3. **25–38 секунд — пересечения, конфликт и заключение.** Показать одну прямую пару пересекающихся обязанностей, потенциальное совмещение контроля и планирования, затем итоговое заключение с рекомендациями и источниками. Все пять обязательных результатов показаны на комплекте организатора.
4. **38–58 секунд — возможная переформулировка без общих слов.** Перейти в синтетический пример «Найти переформулировки». Показать предложенную пару об обращениях клиентов и журнале заявок: слова различаются, но модель нашла повод сравнить обязанности. Прочитать фрагменты, показать владельцев и источник ответа. Подчеркнуть: «0% — сходство слов, не уверенность модели. Это предложение эксперту; основной статус и число возможных утрат не меняются». Если пары нет, показать фактическое состояние проверки вместо обещания результата.
5. **58–72 секунды — одно слово меняет полномочие.** Перейти в синтетическую «Контрпроверку»: «вправе согласовывать» → «не вправе согласовывать». Показать подсветку, точные источники и возможность передать вопрос на согласование. Высокое сходство текста не означает сохранения полномочия.
6. **72–90 секунд — результат для работы.** Вернуться к отчёту поиска переформулировок и выгрузить Excel из плана. Показать «Комплект документов», «Смысловая проверка» и переход к точной цитате; в «Плане решений» доступны решения пользователя. Завершить: «На выходе — проверяемый отчёт и проект решений: видно, что найдено, что осталось проверить и на какие пункты опирается вывод».

## Если есть ещё минута

В обычном учебном примере предложить владельца для архивной функции, добавить обоснование и сохранить решение. Показать проект формулировки с пометкой о согласовании. Затем открыть паспорт «Что вошло в анализ» и пример загрузки 2+2 файлов: исходные имена и совпадающие номера пунктов остаются различимыми. Обзор потенциальных утрат организатора: `docs/loss-review.md`.

## Что отвечать на вопросы

- **Где ИИ?** `gpt-4.1-mini` проверяет найденные сопоставления, `gpt-4.1` ищет возможные переформулировки для пунктов без пары. Трассировка различает API, сохранённый ответ и недоступный шаг. Основные пять результатов доступны на локальном ядре.
- **Модель автоматически исправляет отчёт?** Предложения модели показаны отдельно. Они не меняют статусы функций, находки плана или счётчики. Даже похожий смысл не доказывает передачу ответственности.
- **Можно ли доверять ссылкам?** Адреса и цитаты проверяются по разобранным файлам; смысловой поиск принимает только дословные фрагменты из допустимых источников. Это подтверждает источник, а не правильность интерпретации. Свободный текст модели не публикуется.
- **Как измеряли смысловой поиск?** В зафиксированном прогоне 23/24 совпадения статуса и адреса, одна пара о доставке материалов пропущена. Ошибочных предложений эквивалентности по разметке — 0. Тесты, ожидания и неудачные версии измерений открыты. Порог 24/24 не достигнут: оценочная команда возвращает 1. Наборы малы; отдельный `semantic-blind` также использован для сравнения моделей, поэтому это не полностью независимая финальная оценка. Подробности — `docs/semantic-evaluation.json` и `docs/semantic-review.md`.
- **Что ограничено?** На один смысловой поиск — до 12 исходных функций без пары, 80 пунктов новой редакции, 64 000 символов входного JSON и 4096 выходных токенов. Интерфейс показывает охват. Пункты без результата остаются непроверенными; отсутствие предложенной пары не означает доказанную утрату. Контрпроверка покрывает явные признаки отрицания, модальности, сроков и охвата, а не любые изменения смысла.
- **Что сохраняется?** Решения хранятся в браузере по отпечатку комплекта, до 20 отчётов — на сервере в течение двух часов. После перезапуска нужен повторный анализ. Первый модельный ответ для ключа запроса сохраняется без перезаписи повторными запусками; воспроизведение обозначается как `fixture`.
- **Это система согласования?** Это прототип подготовки плана: нет пользователей, подписей и истории согласований. Excel содержит рабочий проект, который должен рассмотреть ответственный сотрудник.
