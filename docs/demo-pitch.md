# Демонстрация OrgDiff — 90 секунд

## Основная мысль

«При реорганизации важно не только найти расхождения. Нужно понять, кто отвечает за функцию теперь, проверить спорное место и подготовить решение, которое можно согласовать. OrgDiff соединяет эти действия и сохраняет источники».

## Маршрут

1. **0–15 секунд.** Нажать «Проверить учебный пример». Объяснить, что это открытые синтетические данные с заранее заданными изменениями. Для реального комплекта есть отдельная кнопка.
2. **15–30 секунд.** На карте нажать связь ОД → ОК. Раскрыть источники. Показать одну и ту же обязанность в разных подразделениях: это передача, не утрата. Переключиться на «Без найденного соответствия»: показать архив протоколов.
3. **30–55 секунд.** Открыть «Разобрать находки». Выбрать архив, предложить ответственного — Отдел аналитики. Написать обоснование: «Предлагается передать хранение архива отделу аналитики после согласования сроков и порядка передачи». Источник уже отмечен. Сохранить.
4. **55–70 секунд.** Показать изменение счётчиков: рассмотрена одна находка, остаются две. Прочитать проект формулировки. Подчеркнуть: исходные документы не изменились; это решение пользователя для согласования, а не автоматическое объявление риска устранённым.
5. **70–90 секунд.** Нажать «Выгрузить план в Excel». Открыть лист «План решений», затем перейти по ссылке к цитате. Закончить: «На выходе — проверяемое решение с основанием, ответственным и проектом формулировки».

## Если есть ещё минута

Запустить комплект организатора. Показать более сложную карту, раскрыть перенос пункта 5.4.4б → 5.3.3б, открыть кандидата на утрату с похожими фрагментами. Пояснить, что одна прежняя ложная утрата исключена как вводная к перечислению; оставшиеся четыре требуют содержательной проверки. Обзор проверки: `docs/loss-review.md`.

## Что отвечать на вопросы

- **Где ИИ?** Сопоставление и выводы доступны локально. При наличии ключа модель дополнительно проверяет сопоставления по цитатам. Трассировка показывает реально полученные ответы; локальный результат не выдаётся за живой вызов модели.
- **Можно ли доверять ссылкам?** Пункты и цитаты берутся из парсера. Решения плана принимаются только для находок в отчёте, хранящемся на сервере; произвольный присланный отчёт не используется. Это проверка принадлежности источника, а не автоматическое доказательство правильности решения пользователя.
- **Что сохраняется?** Решения сохраняются в браузере по отпечатку комплекта. На сервере временно хранятся до 20 отчётов в течение двух часов. После перезапуска нужен повторный анализ; для того же комплекта можно восстановить решения из браузера.
- **Это система согласования?** Нет: это прототип подготовки плана. Нет пользователей, подписей и истории согласований. Для передачи результата предусмотрен Excel с пометкой «ПРОЕКТ».
- **Как проверяли?** Контрольный комплект организатора, независимые XLSX, негативные проверки источников и владельцев, проверка содержимого Excel и сквозной браузерный сценарий.
