## Что готово

Основной путь реализован: загрузка двух комплектов → определение подразделений → сопоставление функций между комплектами → находки с цитатами → заключение. На каждую редакцию принимаются 1–5 файлов DOCX, текстового PDF или XLSX; форматы можно смешивать. Лимит файла — 20 MiB, суммарно двух редакций — 100 MiB (1 MiB = 1 048 576 байт; в интерфейсе обозначено как МБ). Контрольный комплект организатора и независимые учебные комплекты доступны без API-ключа.

| Обязательное требование | Реализация и доказательство | Граница применения |
|---|---|---|
| Реорганизованные, сохранённые и созданные подразделения | `analysis/units.js`; тесты контрольного состава, переименования, слияния и разделения | Нужны распознаваемые названия и явные основания преобразования; сходство названий не доказывает преемственность |
| Сопоставление функций и потенциальная утрата | `analysis/diff.js`; известные передачи организатора и независимый пример утраты | Сопоставление по словам и владельцам; глубокая переформулировка может остаться без пары. Утрата всегда потенциальная |
| Дублирование и конфликт интересов | Прямые пары пересечений, проверка совмещения контроля качества и планирования | Детектор конфликтов реализует конкретное правило, а не универсальную проверку разделения полномочий |
| Источник каждого существенного вывода | Цитаты парсера с именами файлов; `analysis/evidence-audit.js` проверяет весь выдаваемый отчёт, обе редакции, принадлежность файлам и фрагменты контрпроверки | Совпадение адреса и текста не доказывает правильность интерпретации |
| Понятное итоговое заключение | `llm/enrich.js`, `ConclusionSection.tsx`; наблюдения, рекомендации и источники | Заключение формируется из найденного. При неопределённых владельцах явно сообщает о неполном анализе |

Обязательные артефакты есть: исходники, интерфейс загрузки и просмотра, собранный фронтенд, README с запуском и архитектурой, контрольные данные и воспроизводимые проверки.

## Что исправлено при этой проверке

- Комплекты поддерживают несколько файлов на сторону. Интерфейс дополняет выбор, позволяет удалять отдельные файлы и сохраняет прежний выбор при невалидной подборке. API принимает повторяющиеся multipart-поля `before` и `after`; лимиты проверяются на сервере.
- Файлы разбираются отдельно: совпадающие номера пунктов в разных приложениях не смешиваются. В многодокументной редакции адрес содержит идентификатор файла на основе хеша его байтов; перестановка неизменённых файлов не меняет ссылки. Для одного файла сохранён прежний формат адресов. Побайтовая копия в той же редакции отклоняется с объяснением; одинаковый файл в двух редакциях допустим.
- Определения подразделений из файлов объединяются внутри редакции; противоречивые названия и аббревиатуры отклоняются. Явно названный владелец разрешается по составу всей редакции, общий заголовок действует только в пределах состава своего файла. Сопоставление функций и поиск пересечений выполняются по всему комплекту.
- Короткая подпись подразделения в XLSX, например «ОК», связывается с определением «Отдел контроля (ОК)» из комплекта с сохранением источников обоих определений. Явная аббревиатура в заголовке имеет приоритет перед совпадениями отдельных слов названия.
- Состав файлов виден в отчёте и на листе Excel «Комплект документов». Цитаты, источники решений и контрпроверка показывают имя исходного файла. Паспорт содержит отдельные показатели каждого файла. [Снимок четырёх файлов](screenshots/12-document-collection.png).
- Повторные числовые номера пунктов больше не перезаписывают источники и владельцев: неоднозначный документ отклоняется с объяснением. Повторные буквенные списки сохраняют отдельные адреса; явное оглавление не подменяет разделы.
- Продолжение буквенного подпункта прикрепляется к его цитате.
- Короткие обязанности вроде «Согласует договоры» не исчезают из-за порога длины.
- Заголовок «Руководитель службы поддержки» распознаётся без обязательной аббревиатуры.
- Обязанности явно названной роли без отдельного подразделения включаются в сравнение под названием роли. Это вернуло в анализ 20 пунктов 5.3 редакции 8; подразделения из ролей не создаются. Три новых кандидата на утрату разобраны в `docs/loss-review.md`.
- Строки XLSX без определённого подразделения сохраняются как источники предупреждений, а не исчезают.
- Паспорт «Что вошло в анализ» показывает распознанные пункты, владельцев, пропуски и общие назначения. Полнота не выражается вымышленным процентом.
- Проверка цитат выполняется перед каждым ответом API, а не только в тестах. Паспорт и его источники также попадают в Excel.

## Что ещё остаётся

**Для более широкого применения:** OCR и оргсхемы; смысловое сопоставление свободных переформулировок; дополнительные правила конфликта интересов. Комплекты ограничены 5 файлами на сторону и распознаваемой структурой. Нормативные пробелы определяются по ограниченным признакам упоминания подразделений и описания функций, без юридической проверки. Общие заголовки даже в пределах своего файла могут требовать более узкой интерпретации. Нераспознанные конструкции могут остаться вне диагностики даже при отсутствии предупреждений.

**Стабильность источников:** идентификатор файла зависит от его байтов, поэтому повторное сохранение DOCX/XLSX может изменить его даже при неизменном видимом тексте. Гарантируется независимость ссылок от порядка одинакового набора неизменённых файлов; добавление второго файла переводит адреса из совместимого одиночного формата в формат комплекта. Отсутствие распознанных функций в отдельном приложении отражается в паспорте, но не доказывает отсутствие обязанностей в его содержимом.

**Для проверки модельной части:** подтверждённый живой прогон модели на разрешённых данных и оценка её вклада. Текущая модельная интеграция только дополнительно проверяет уже найденные сопоставления; автономность и основной сценарий обеспечивает локальное ядро. Наличие кода интеграции не считается доказательством успешного вызова API.

**Опциональные пункты задания:** законодательство/стандарты и сравнение с другими операторами не реализованы. Предложение перераспределения функций реализовано как рабочий план пользователя с обоснованием, источниками и проектом формулировки.

**Сдача:** наличие коммитов не подтверждает отправку решения на платформе. Публикация, push и статус сдачи этой проверкой не устанавливались.

## Как воспроизвести

1. `cd server` и `npm test` — независимые примеры, форматы и комплекты, регрессии, API, проверка подмены цитат, план и Excel. Тесты комплектов включают совпадающие номера в разных файлах, перестановку, повторные копии и ограничения загрузки.
2. `npm start` — оставить сервер в этом терминале, открыть `http://localhost:3000`, проанализировать комплект организатора и раскрыть «Что вошло в анализ».
3. В другом терминале из `server`: `npm run verify` — 21 контрольная проверка документов организатора, включая точное совпадение цитат.
4. «Проверить учебный пример» — переименование, передача, утрата и пересечение.
5. «Найти скрытые изменения» — четыре изменения формулировок, рассмотрение с источниками и экспорт.
6. Добавить несколько файлов в каждую редакцию и запустить анализ загруженных документов. Проверить состав отчёта, имена рядом с цитатами, отдельные строки паспорта и лист «Комплект документов» в Excel.
7. При запущенном сервере и отдельном тестовом Chrome на порту 9333 открыть другой терминал в `server` и выполнить `node scripts/browser-smoke.js`. Сценарий включает загрузку XLSX со строкой без владельца, четыре файла с совпадающими адресами строк, имена источников, решения и экспорт. Флаг `--screenshots` сохраняет снимки сценария.
